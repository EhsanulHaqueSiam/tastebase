What gets built (same for A, B, C)

01 · registry

One curated dataset

Components, libraries and inspiration sites live as typed files in the repo. Each entry has a note on why it is good, a source URL and tags. The site, the CLI and the MCP server all read this one dataset.

02 · site

The premium browser

Vite, React, Tailwind and TanStack Start, deployed as a static site to Cloudflare. Live component previews, ⌘K search, and Trending.

03 · agent

CLI + MCP + skill

npx tastebase is the CLI, and npx tastebase mcp is the MCP server built from the same binary. A Claude Code skill tells the agent when to use it: before any UI work, search, pick, then install.

04 · hot

Trending job

A daily GitHub Action pulls star deltas from the GitHub API and weekly downloads from the npm API for every library in the registry, then commits trending.json. That needs no server and no database.

# what Claude Code does with it
tastebase search "toast stack" --json      # ranked picks with why-notes
tastebase trending --week                  # rising libraries and components
tastebase add toast/stack                  # copies source in, shadcn-registry style
tastebase inspo "dark dev-tool pricing"    # reference sites with screenshots

Not in v1: accounts, user submissions, a paid tier, or a hosted search API. The registry is plain files, so search runs locally inside the CLI.
